# Microarchitecture

## Pipeline stages

Each `E` marks a clock edge that captures instruction state; `E0` is the registered fetch PC. Logic between two edges belongs to the following stage. These examples assume ready operands, available queues, L1 hits, no redirects, and same-edge ROB allocation/DPU dispatch. The load and store examples use aligned, cacheable Bare-mode accesses with no older-memory conflict; the load enters an empty IOQ, so it can enter the registered request stage directly in every preset. Each Backend line continues the Frontend line above it.

```text
Integer (simple ALU port):
Frontend: E0[PC](IFU) -> E1[Fetch](L1I) -> E2[Packet](IFU) -> E3[Queue](FQU) -> E4[Decode Input](IDU)
Backend:  E5[Decoded Queue](RNQ) -> E6[Rename](RNU rename_pipe) -> E7[Operand Stage](rapt_operand_stage) -> E8[Operand Read](PRF+UOQ) -> E9[Allocate and Dispatch](ROB+DPU+ALQ) -> E10[Execute / Accepted Completion](ALU+CDB+completion register) -> E11[Writeback](ROB_WB) -> E12[Commit](ROB)

Load:
Frontend: E0[PC](IFU) -> E1[Fetch](L1I) -> E2[Packet](IFU) -> E3[Queue](FQU) -> E4[Decode Input](IDU)
Backend:  E5[Decoded Queue](RNQ) -> E6[Rename](RNU rename_pipe) -> E7[Operand Stage](rapt_operand_stage) -> E8[Operand Read](PRF+UOQ) -> E9[Allocate and Request](ROB+DPU+IOQ) -> ...[Cache Access / Response](L1D+IOQ) -> E_L[Accepted Completion](CDB+completion register) -> E_L+1[Writeback](ROB_WB) -> E_L+2[Commit](ROB)

Store:
Frontend: E0[PC](IFU) -> E1[Fetch](L1I) -> E2[Packet](IFU) -> E3[Queue](FQU) -> E4[Decode Input](IDU)
Backend:  E5[Decoded Queue](RNQ) -> E6[Rename](RNU rename_pipe) -> E7[Operand Stage](rapt_operand_stage) -> E8[Operand Read](PRF+UOQ) -> E9[Allocate and Dispatch](ROB+DPU+IOQ) -> ...[Address / Permission Check](IOQ) -> E_S[Accepted Completion and Buffer](CDB+completion register+SQ) -> E_S+1[Writeback](ROB_WB) -> E_S+2[Commit](ROB) -> ...[Drain](SQ)
```

`E_L` and `E_S` denote the accepted load/store completion edge, not a fixed offset from dispatch. At that edge, accepted results wake operand holders and enter `rapt_completion_stage`; ROU consumes the registered packet at the next edge and sets `ROB_WB`. Commit requires the stored `ROB_WB` state, so the earliest retirement is the following edge, provided the owner is in the ready head prefix. Reset or flush kills the completion.

These are ideal edge sequences, not fixed instruction latencies: L1I may read a sequential word, or a redirect target, ahead of `E1`; queue or operand waits, `ROB_DP` residence, translation, cache misses, replay, and bus responses extend a path. RNQ, `rename_pipe`, the operand stage and UOQ are registered without empty-queue fall-through, so each costs one edge even when empty. Store drain occurs after architectural commit. In the write-through `default` preset it is a bus write. With the default `RAPT_POSTED_WRITES=4`, an eligible cacheable store releases the SQ head when AXI accepts the write, and up to four such writes can wait for their B responses. Device, uncacheable and ineligible stores hold the head until B. In an L1D write-back configuration (`default-l2`), an eligible cacheable hit completes locally. The default `RAPT_FETCH_RESPONSE_STAGE=0` adds no IFU response register. All presets register accepted completions before ROB writeback and retirement; operand wakeup uses the accepted packet before this register.

An earlier default RV32 waveform recorded `addi` retirement at `E11` and store SQ entry/retirement at `E11`/`E12`. Its source revision is not recorded here; those observations do not validate the current registered completion path.

## Organization

Raptor is a configurable RV32/RV64 out-of-order core with a two-wide default preset. `rapt_core` composes `rapt_frontend` (prediction, fetch, FQU, decode), `rapt_backend` (rename, operand stage, ROB, dispatch, issue, completion, LSU, precise commit), and `rapt_memory` (L1I, L1D, translation, bus, optional L2). The composition boundaries themselves add no registers. The default decode, rename, dispatch, and commit widths are each two; instruction queues hold individual instructions rather than fixed pairs.

The [pipeline explorer](./explore.md) is an illustrative cycle model. It does not model current branch recovery, MSHR replay, or the direct integer completion path, so its cycle counts are not RTL timing or CoreMark IPC.

## Frontend: Fetch, queue, and decode

- **IFU and L1I:** The IFU walks complete 16/32-bit instructions in a six-halfword (three-word) L1I lookahead window, keeps any unconsumed suffix in a register, and ends a fetch group at a taken control, serializing, or faulting instruction, or before a second control instruction. A non-first `jalr` starts a new group so the BTB can be queried at its PC. `default-w4` and `default-w8` widen the window to eight halfwords (`RAPT_FETCH_WIDE`); all presets allow a group to continue past a predicted-not-taken conditional branch until the next control instruction, within the available fetch width. L1I is a 16 KiB, four-way cache with 64-byte lines, stored as four independently addressed 128-bit synchronous SRAM banks per way; pre-reads can hide the SRAM cycle for sequential fetch and for line crossings. A miss refills a 32-byte sector (`RAPT_L1I_REFILL_WORDS=8`) with individual AXI reads. The optional IFU response register is disabled in the generic default preset and enabled by the fixed RV64 netboot profile for presets other than `default-w4`. Miss refills, translation faults, and accepted-request ownership remain in L1I.
- **FQU and IDU:** FQU is a four-entry registered stream queue without empty-queue fall-through; it can regroup instructions across fetch packets. IDU registers its input, decodes each slot combinationally, and corrects accepted direct jumps, return predictions, or stale targets before rename. Flush and recovery invalidate resident frontend instructions.
- **BPU:** The default direction predictor is TAGE (a 1024-entry bimodal base plus three 1024-entry tagged tables with 8/16/64-bit histories in `default` and `default-w4`; the shared fallback is 256 + 3 x 128), with selectable gshare, bimodal, or static alternatives. Each preset must define exactly one `RAPT_BPU_DIRP_*` selector; if build flags introduce multiple selectors, RTL precedence is TAGE > GSHARE > BIMODAL > STATIC. Defining none causes a preprocessing error; static prediction requires an explicit selector. With lookahead, a packet's first non-first conditional branch uses TAGE's auxiliary read port whenever TAGE is selected; non-TAGE predictors supply not-taken for that query. This is shared behavior, not a separate preset switch. A 128-entry, two-way BTB supplies targets for the packet's first PC; IDU resteers and commit-time mispredictions train it. Prediction queries alone do not advance history: accepted conditional instructions update it speculatively at fetch and decode. A misprediction announcement restores GHR/PHR from its rename checkpoint, and a full flush restores the committed history. The RAS (16 entries in `default`) is updated at decode and restored from a committed copy on flush. TAGE trains at retirement.

The predictor query PC is `ifu_bpu.nextpc`; the redundant `ifu_bpu.pc` field was removed. `idu_bpu_if` no longer carries `history_auxiliary` or `history_auxiliary_index`, or the unused `PHT_SIZE` parameter. Accepted history events use the remaining history fields.

## Backend: Rename, dispatch, and execution

- **RNU and PRF:** The eight-entry RNQ stores decoded instructions; RNU maps architectural GPRs to a 64-entry physical register file, resolves dependencies within a rename group, and writes a separate registered `rename_pipe` output queue (`2 x RenameWidth` entries). A separate `rapt_operand_stage` holds one renamed group before the ROU's eight-entry UOQ reads PRF operands asynchronously and keeps listening for completions. Commit updates the architectural RAT and releases stale mappings; a full flush rebuilds speculative MAP/free state from committed state. Branch checkpoints are a separate bounded resource: 16 by default, each holding GHR/PHR, a conditional-branch flag, and an ancestor set. They do not snapshot MAP/free state; that state is rebuilt from the post-commit RAT at the precise flush.
- **ROU and DPU:** UOQ feeds a 32-entry ROB with states `ROB_DP -> ROB_EX -> ROB_WB -> ROB_CM`. A ready allocation can bypass `ROB_DP` and enter an execution queue on the same edge. Wide integer operand values for owners waiting in `ROB_DP` live in an operand spill bank (16 entries in `default`, eight in `default-w4`) rather than in every ROB slot. DPU is a capacity-aware selector: it scans the registered dispatch window (12 lanes by default) and sends at most `DispatchWidth` full payloads to eligible domains. A blocked domain can leave an owner resident in `ROB_DP` while other domains progress. Every preset uses `rapt_rob_dispatch_window`: ranked resident owners and carried allocation lanes are registered, alongside live allocation candidates. The default window has eight ranked, two carried and two live lanes, so full-ROB ranking does not feed operand reads and queue writes in the same cycle. `default-w4` uses four ranked, four carried and four live lanes.
- **Issue queues:** The default ALQ has eight entries and two integer issue ports, including in `default-w4`; BRQ has eight entries and MDQ has four, the scalar FPQ has one, and IOQ has eight. Integer/branch/FP issue queues capture operands and wake on accepted completions; ALQ selection and the simple ALU execute in the same cycle. Current IQ instances use the default `ReclaimOnIssue=0` module parameter in every preset: a slot issued on an edge cannot be reused on that same edge. This delays reuse without adding an execution stage.
- **Execution and completion:** One integer port owns CSR/system operations and shares its completion endpoint with scalar FP; the other simple ALU port remains independent. Branches use a separate compare path, and MUL/DIV uses a private queue with pipelined multiply and an iterative divide that skips the dividend's leading zero bits in one normalization cycle and then resolves two quotient bits per cycle (about 2 + ceil(significant dividend bits / 2) cycles). For `N` integer ports the guarded fabric has `N+3` outputs: `N` integer, one branch, one memory, and one MUL/DIV. Integer, branch, and memory results reach the common completion fabric directly; MUL/DIV drives its endpoint from the functional unit's registered output in every preset. All accepted completions wake operand holders on their acceptance edge and enter a completion register. ROU writes back the registered copy on the next edge; retirement is possible on the following edge. Recovery also consumes the registered copy, and speculative fast-load wakeup is disabled in every preset. Scalar FP results pass through the shared-port buffer. A ROB slot plus a 4-bit allocation generation identifies each live producer before it can affect ROB, PRF, or wakeup state.
- **Floating point and commit:** FEU owns scalar F/D and Zfhmin arithmetic, including FMA and divide/square root. The architectural FPR file is two replicated 32x64-bit synchronous two-port RAMs (FMA `rs1`/`rs2` on one, `rs3` and the IOQ store operand on the other); every write goes to both. FP loads/stores use LSU. Current scalar FP and CSR operations serialize at an empty ROB. ROU commits a ready prefix in order, up to two instructions by default; special effects retire alone. An ordinary group admits at most one store and one control-flow instruction. In every preset, ordinary instructions may retire after that store; a second store cannot. CMU broadcasts retirement, redirect, fence, and trap effects; CSR holds privilege, translation, interrupt, and PMP state.

## Memory: LSU, L1D, translation, and bus

- **LSU:** IOQ computes addresses through one per-entry preparation register, checks older-store dependencies, and can issue a younger ready load when older stores are resolved and nonconflicting. Atomics and uncacheable/MMIO accesses remain ordered at the IOQ head. An aligned full-width store in the unified 16-entry SQ may forward to a load contained in the same word; unresolved or stale-context stores block unsafe forwarding. All presets allow contained narrow-load forwarding in Bare mode; partial overlap without full byte coverage still blocks. The IOQ allocates a store's SQ entry when its completion is accepted; ROB commit marks that entry committed; the SQ drains committed entries in order to L1D or the bus. Flush discards speculative SQ entries but preserves committed ones. In every preset, a load whose base arrives on an eligible completion can form its address directly in the registered request stage; memory-port results are excluded, so a load result cannot close the request register through the L1D response and SQ forwarding in one cycle. All presets also sample older-store disjointness and ordering before early completion and precheck the oldest ready eligible resident store's permission.
- **Memory completion contract:** Load, store, and atomic results use one typed IOQ completion packet and one owner check before ROB writeback. A store-side permission fault takes priority over an atomic read fault; a non-faulting completion reports zero exception cause. A same-cycle reset or pipeline flush suppresses the completion and speculative SQ handoff, while already committed SQ entries retain their independent drain lifetime. An early younger-load broadcast is restricted to a clean result and keeps its IOQ entry until ordered removal. Fast-load confirmation is issued only for a load result; an SC completion cannot itself confirm a fast load. The store permission check remains registered; an ordinary L1D hit can use the direct response path when `RAPT_IOQ_LOAD_RESPONSE_STAGE=0`. Setting that macro to `1` captures the response before completion and disables live response wakeup across that boundary. In every preset, the SC reservation decision is registered, and the SQ load path registers PMP decisions when they cannot bypass. The memory endpoint checks the ROB owner contract with a verification assertion rather than a combinational owner lookup. The shared completion register described above is after accepted operand wakeup; there is no separate preset-controlled memory completion register before CDB fanout.
- **Wider configurations:** This contract is lane independent, but the current IOQ still presents one memory completion packet per cycle and the L1D A/B load paths share one data SRAM read port. Raising dispatch and integer issue widths to four, eight, or sixteen does not add memory completion or hot-hit read bandwidth. If a fraction `f` of committed instructions needs this memory completion port, its steady-state IPC ceiling is `min(issue width, 1/f)`, even with perfect frontend and cache hits. A future multi-lane LSU must apply the same owner, exception, flush, and SQ handoff rules to each accepted packet; then it needs explicit completion arbitration, enough cache banks/read ports, and SQ admission bandwidth. With sixteen integer lanes, the current `N+3` completion fabric already has nineteen broadcast endpoints, so banked/distributed wakeup and physically local completion paths also need measurement before adopting that width. Widening dispatch alone does not provide those resources.
- **L1D:** The default 16 KiB, four-way L1D has 64-byte lines, banked synchronous SRAM, separate load/store DTLB lookup replicas, and a shared data PTW. A hit returns from the registered access state; misses may park in the default two physical-line MSHRs and replay from IOQ after a wake. While the A channel waits on a miss, a best-effort B channel (`RAPT_LSU_HUM`) can serve a younger load that hits cleanly or forwards from the SQ. Same-line misses share a refill, while MMIO, atomics, and some split accesses use the blocking path. Demand data can return before the last refill beat, but the accepted bus owner remains live through the final beat.
- **Store policy:** The ordinary `default` preset uses write-through. `default-l2` sets `RAPT_L1D_WRITEBACK=1` for the core, simulation wrappers, memory subsystem, and direct L1D instances. Write-back mode locally completes eligible cacheable store hits, tracks dirty words, and releases a dirty line to the inclusive L2 when probed; it disables L1D MSHRs while active. A bus write-back error latches `writeback_error_o` and stops affected traffic until reset. DMA coherence remains a platform/software responsibility.
- **Translation and protection:** Fully associative ITLB and load/store DTLBs have 16 entries each by default; separate instruction and data PTWs implement Sv32/Sv39. PMP checks fetch, data, and PTW accesses. Split loads carry both their architectural width and each physical fragment's permission footprint, so a narrower fragment cannot bypass a device-width restriction.
- **Cache-block operations:** `cbo.inval`, `cbo.clean`, and `cbo.flush` check the translated address before retirement, then wait for the SQ to drain; invalidation/flush remove matching L1D blocks. `cbo.zero` commits an aligned 64-byte zero descriptor through SQ and waits for its final write response. Zicbop prefetch encodings are nonfaulting hints.
- **Bus:** `rapt_bus` arbitrates L1I, L1D, and PTW requests; `rapt_axi_master` supports up to eight outstanding reads. Without L2 and with a write-through L1D, it accepts up to `RAPT_POSTED_WRITES` (default four) posted cacheable writes; otherwise one write is outstanding. A read cannot overtake a posted write to its line, and an uncacheable read waits for every posted write. A failed posted write's B response reports the affected line to L1D. The default preset leaves L2 as a combinational passthrough. The outer AXI R channel has a two-entry registered buffer when `RAPT_L2_STORE_WRITEBACK` is defined (as in `default-l2`); the generic default bypasses it.
- **Optional L2:** `default-l2` enables a 512 KiB, eight-way L2 with 1024 sets and 64-byte lines. Eight 1024x22 directory SRAMs hold tag/state/dirty/client metadata. Four logical 16384x64 data banks support Vivado RAM inference and optional segmented SRAM macros. This banked geometry stores 18 tag bits and bypasses addresses above its 34-bit cache-address aperture instead of truncating them into an alias.
- **L2 reads and coherence:** Independent clean misses use three ordinary refill contexts in RV32 or five in RV64, interleave outer responses by ID, and return the critical scalar word early. The shared secondary buffer has 15 queues/35 entries in RV32 and 21 queues/33 entries in RV64. Same-tag requests reuse current metadata; different tags re-read the directory. A foreign Get probes a Trunk L1D owner before reading its latest data. C Release can pre-empt a waiting victim/CBO Probe and forward its updated dirty/client metadata. The main L1D replies by invalidating its copy; retained Branch copies and permission upgrades are not enabled.
- **L2 writes:** A 40-list/40-beat Put pool and 40 ordered B slots retain incoming writes. Bufferable scalar stores and supported narrow, masked, FIXED, INCR and WRAP bursts allocate each touched cacheable line. Partial misses merge a refill; complete full-line writes skip the outer read. Non-bufferable writes forward, preserve resident dirty data on an outer error, and commit their resident-byte journal only after successful B. Dirty/client-owned victim misses and allocated Put execution remain serialized.
- **L2 limits:** The reserved scheduler and connected C Release paths do not implement general nested BC/C transitions or independently executing allocated Put lists. SourceD staging still differs from BOOM. Only the L1D is a probe-capable client. CBO write-back failures retain dirty data and stall maintenance; there is no software-visible CBO error report, and a later eviction error cannot be attributed to an already completed store. These limits and FPGA timing acceptance are tracked separately from the passing functional regressions.

Load scheduling conservatively waits behind older stores with unresolved addresses. There is no learned memory-dependence predictor or speculative RAW-violation rollback, and there is no independent data hardware prefetcher. MSHR miss replay, branch-target SRAM read-ahead, and Zicbop hints serve different purposes. Candidate studies and measured limits are recorded in `docs.agent/evaluation/raptor-modern-mechanisms-2026-10-09.md`.

## Recovery and platform control

A nonfaulting branch misprediction produces a registered oldest-owner recovery transaction containing its ROB slot, allocation generation, target, and checkpoint identity. On the announcement, the rename checkpoint restores the predictor's GHR/PHR, and IFU may read the target SRAM early. While `recovery.pending` is set, FQU, IDU, RNQ, `rename_pipe` and the operand stage are emptied, frontend delivery stops, and the recovery fence stops new ROB allocation in every preset; older ROB work continues until the mispredicted instruction reaches the head. Retirement then performs the precise whole-pipe flush and reconstructs rename state from committed state. The announcement selectively cancels younger integer/branch issue entries, issue packets, and MUL/DIV owners. MUL pipeline and iterative DIV state are removed before an MDQ slot can be reused; older operations and the recovery owner survive. ROB/IOQ/SQ and rename still use the retirement-time precise flush, so correct-path execution cannot restart at the announcement. Correct branch resolutions release checkpoints independently, and completion ownership guards reject stale generations. The 4-bit generation guard is used together with producer cancellation and flush ownership; its finite width alone does not establish safety for arbitrarily late completions.

The CSR file supports M/S/U privilege, traps, delegation, Sv32/Sv39 controls, and cycle/time state. Eight PMP entries implement TOR, NA4, and NAPOT across 16 architectural CSR slots; slots 8-15 read as zero and ignore writes. The cluster routes CLINT timer/software interrupts and PLIC external interrupts to the core. CLINT supplies `mtime`, `mtimecmp`, and `msip`; PLIC has 31 sources and M/S contexts by default. The PLIC window accepts naturally aligned 32-bit ordinary loads/stores; other ordinary widths fault before a device access.

The standalone `rapt_rnu_freelist` module and its `rnu_fl_if` interface were removed; rename free state remains in RNU, and `rapt_rnu_maptable` remains available for formal checks. CSR observers read `csr_bcast.mtvec`; the duplicate `exu_csr_if.mtvec` field was removed. The instruction bus interface `l1i_bus_if` no longer exposes unused `rlast`, `wready`, or `werr` fields; IPTW write-response signals are unchanged.
